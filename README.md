# Python for Data Analysis

A free, open-source study guide to Python for data analysts: the tools around Python, the language basics, pandas, NumPy, statistics with SciPy, charts with matplotlib and seaborn, the errors that appear after recent library changes, common challenges in analysis work, and flashcards.

It is a static web page (`index.html`) that loads its content from `content/*.json`, so it can be hosted on GitHub Pages and updated by editing data files.

## Open the page

**https://angel-iana.github.io/python-analyst-companion/**

## What is inside

| Section | What it holds |
|---|---|
| Study path | A map of modules with progress bars, then the entries in a suggested order, from the first tools to the pitfalls of recent versions. A checklist is saved in your browser. |
| Reference by tool | Every entry, grouped by tool and group, with filters for tool and level. Many entries have a "Try it" box: an interactive text slicer, a line-by-line view of how variables change, or a predict-then-check exercise. |
| Common errors | Changes in recent pandas and seaborn versions that break older code. |
| Common Challenges in Data Analysis | Questions analysts run into in everyday work, grouped in five themes. |
| Flashcards | One card per entry plus cards for single facts. Progress is saved in your browser only. |
| Sources | The documents the entries link to. |

Every entry has a short explanation in plain words, a code example when one helps, and the **real output** of that code, produced on the versions below. Where a database or spreadsheet equivalent helps, it is named (`GROUP BY`, `JOIN`, `VLOOKUP`).

## Versions used for the examples

Python 3.15.2, pandas 3.1.0, NumPy 2.5.4, SciPy 1.18.1, matplotlib 3.11.2, seaborn 0.13.2. The same list is in `requirements.txt` and `content/meta.json`.

## Run it locally

```
python -m http.server
```

Then open `http://localhost:8000`. Opening `index.html` directly from the file system does not work, because browsers do not allow a page to load data files that way.

To run the code examples yourself:

```
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt     # Windows: .venv\Scripts\python.exe
python tools/run_blocks.py
```

## Check the content

| Command | What it does |
|---|---|
| `python tools/run_blocks.py` | Runs every code block and compares its output with the stored output. Add `--update` to rewrite the stored outputs. |
| `python tools/check_terms.py` | Looks for terms that must not appear in published files. |
| `python tools/check_links.py` | Checks that every source link answers (needs internet). |

A GitHub Actions workflow can run the first two on every pull request.

## Contribute

Anyone can add or correct an entry. Read [CONTRIBUTING.md](CONTRIBUTING.md) first: entries are written in your own words, the output is generated by running the code, and what could not be verified is marked "to be confirmed".
